01 · El ciclo DevOps

DevOps no es una herramienta: es una forma colaborativa y automatizada de construir, entregar, operar y mejorar software. Pulsa una fase para aprender su propósito.

Plan · decidir qué construir

🧩 CI: Integración Continua

Al integrar cambios, un pipeline puede instalar dependencias, compilar y ejecutar tests. Detecta fallos antes de publicar.

Ejemplo: abres un pull request y las pruebas automáticas fallan. No deberías aprobarlo sin investigar.

🚀 CD: dos significados

Continuous Delivery: mantener una versión lista para liberar, con posible aprobación manual.

Continuous Deployment: publicar automáticamente los cambios que superan los controles.

Ningún método significa “subir todo a producción sin comprobar nada”.

💡 Caso real: TaskFlow

Modificas tu gestor de tareas en VS Code → haces commit y push a GitHub → GitHub Actions puede ejecutar pruebas → una versión aprobada puede desplegarse en la nube → el equipo supervisa errores y rendimiento. Git push por sí solo no garantiza despliegue: hay que configurar el flujo.

Trampas frecuentes

DevOps ≠ una aplicación. CI ≠ CD. Hacer push ≠ desplegar. Pasar pruebas ≠ garantizar ausencia de errores. Desactivar tests para que “pase” el pipeline no resuelve el problema.
