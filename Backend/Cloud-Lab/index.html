01 · Comprende

¿Qué es realmente la nube?

Una forma de acceder por Internet a infraestructura y servicios informáticos de terceros. No es magia: son máquinas reales en centros de datos.

🏠

Servidor en casa

Tu aplicación depende de tu equipo, tu red y la energía eléctrica. Tienes control, pero también responsabilidad operativa.

☁️

Servidor en la nube

Contratas recursos remotos. El proveedor administra la infraestructura física y tú administras lo que corresponda a tu servicio.

🌍

Acceso desde cualquier lugar

Una API desplegada públicamente puede recibir solicitudes desde Internet, siempre que la red, autenticación y permisos lo permitan.

Analogía Feynman: comprar un servidor es como comprar tu propia planta eléctrica; contratar capacidad cloud se parece a pagar por usar un servicio energético. El proveedor mantiene gran parte de la infraestructura, pero tú sigues siendo responsable de usarlo bien.

Los tres recursos que debes dominar

🧠

CPU · Procesamiento

Ejecuta instrucciones. Si se satura, las solicitudes intensivas en cálculo pueden esperar.

📦

RAM · Memoria temporal

Alberga datos durante la ejecución. Cuando falta, puede haber errores o uso de memoria secundaria.

💾

SSD · Almacenamiento

Conserva archivos y datos persistentes. La capacidad no equivale automáticamente a velocidad.

También importa la red, la base de datos, la seguridad y la configuración. La nube no garantiza disponibilidad perfecta ni costos cero.

04 · Toma decisiones

IaaS, PaaS o SaaS

La pregunta no es cuál tiene el logo más bonito, sino cuánto control y responsabilidad necesitas.

🧱

IaaS

Infraestructura como servicio: VM, almacenamiento y redes. Más control y más tareas de administración.

Ej.: AWS EC2
🛠️

PaaS

Plataforma gestionada para desplegar código. Menos trabajo administrando el sistema operativo.

Ej.: Azure App Service
📨

SaaS

Software listo para usar; no desarrollas ni despliegas el producto por tu cuenta.

Ej.: Google Drive
