Primero, la idea sencilla

Una API REST se parece a una biblioteca: el recurso es lo que necesitas, y el método es lo que quieres hacer con él.

¿Cómo viaja una solicitud?

El método acompaña a la ruta: GET /users/1 consulta el usuario 1; DELETE /users/1 solicita eliminarlo.

CRUD: cuatro operaciones, cinco métodos frecuentes

POSTCREATE: crear
GETREAD: consultar
PUTUPDATE: reemplazar
PATCHUPDATE: cambiar parte
DELETEDELETE: eliminar
REST es un estilo arquitectónico, no un protocolo ni un sinónimo de CRUD. HTTP proporciona métodos y códigos; la API define los recursos y sus representaciones.

Rutas de nuestra API de práctica

MétodoRutaFunciónRespuesta habitual

GET/users/1Leer usuario 1200 + objeto
POST/usersCrear usuario201 + objeto

Trampa de examen: 201 significa Created, no «salió bien» de forma genérica. Para borrar o modificar un recurso existente son frecuentes 204 o 200.
