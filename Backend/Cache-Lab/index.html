EXPLORADOR / CACHE-ASIDE

¿Por qué buscar dos veces lo mismo?

Imagina que el vendedor de Capi Bolis anota en una pizarra los precios que más le preguntan. Consultarla es rápido; si no encuentra el dato, revisa el registro original y anota una copia. Esa pizarra representa la caché.

MAPA DE CONCEPTOS
Las reglas de una caché
Una caché puede vivir en el navegador, CDN, aplicación o un servicio compartido como Redis. No es necesariamente una base de datos de origen ni un respaldo.

Controla las consultas al catálogo

SIMULADOR 02 / EVICTION PLAYGROUND
Compara LRU, FIFO y LFU
Ejecuta la misma secuencia de solicitudes desde una caché vacía. Cada letra es una clave. Aquí no hay TTL ni escrituras, solo reemplazo por capacidad. LFU desempata por el acceso menos reciente.
LRU prioriza recencia; FIFO elimina la entrada más antigua por inserción; LFU prioriza frecuencia. La mejor opción depende de la carga de trabajo.

SIMULADOR 03 / HTTP BROWSER CACHE
¿Descargar todo o reutilizar?
Simula un recurso JSON público de 10 KB en el navegador. Un ETag identifica su versión. Con una copia vencida, el navegador puede enviar If-None-Match: si no cambió el recurso, el servidor responde 304 sin cuerpo; si cambió, responde 200 con contenido nuevo.
Modelo de caché privada de navegador, no de CDN. Cambiar la política del servidor no revoca una copia fresca ya almacenada; las nuevas directivas llegan con la siguiente respuesta de red. Para simplificar, no se modelan otros encabezados, tamaños de encabezados, ni concurrencia.
