01 · La idea en palabras simples

La API es el acuerdo para comunicarse.

No es necesariamente un servidor ni una base de datos. Es una interfaz con reglas: qué puedes pedir, cómo pedirlo y qué recibirás de vuelta.

🍽️ El restaurante de las APIs

Toca cada pieza para descubrir su equivalente en una app.

03 · Descifra las rutas
Una API tiene varias puertas: los endpoints.
En /api/tasks/:id, el :id es un parámetro variable. /api/tasks/15 se refiere a una tarea concreta. El método cambia qué operación se solicita.
🧰 Constructor de endpoints
Las rutas de este laboratorio siguen una convención REST común. No todas las APIs usan REST.
🧪 Encuentra el patrón de una ruta
🌐 REST
Estilo de arquitectura. Suele usar recursos, métodos HTTP, representaciones JSON y operaciones sin estado de sesión en el servidor.
📊 GraphQL
Lenguaje de consulta para APIs: el cliente declara qué campos necesita. No es simplemente otro código HTTP.
📦 SOAP
Protocolo de mensajería con estructura XML y contrato definido. No todas las APIs tienen endpoints REST.

⚠️ No caigas en estas trampas
API ≠ servidor: la API define cómo interactuar; el backend puede implementarla.
Endpoint ≠ API completa: el endpoint es una operación específica en una ruta.
401 ≠ 403: el primero trata de credenciales de autenticación; el segundo indica rechazo de autorización.
GET ≠ POST: consultar recursos y procesar/crear recursos tienen semánticas distintas.
🧠 Qué debes recordar
Una API permite que programas se comuniquen mediante reglas y contratos sin conocer necesariamente los detalles internos del otro sistema.
Para practicar todavía más, abre tu laboratorio anterior de HTTP y compara los métodos y códigos de estado.
