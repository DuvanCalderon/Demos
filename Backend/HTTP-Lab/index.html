HTTP es un protocolo de solicitud y respuesta. HTTP es sin estado: cada solicitud se interpreta por sí misma; las sesiones pueden construirse con cookies o tokens.

GET / POST

GET consulta. POST envía información para procesarla, por ejemplo, crear un pedido.

PATCH / PUT / DELETE

PATCH modifica parte, PUT reemplaza la representación indicada, DELETE solicita eliminar.

Headers / Body

Los headers describen el mensaje; el body lleva su contenido, cuando existe. Content-Type indica el formato enviado.

    05. Trampas frecuentes de HTTP

    ✅ Recuerda

    • 200 = éxito general; 201 = recurso creado; 204 = éxito sin cuerpo.
    • 401 = falta autenticación válida; 403 = autenticado pero sin permiso suficiente (según el caso).
    • 404 = recurso no encontrado; 405 = método no admitido para esa ruta.
    • PUT normalmente reemplaza una representación; PATCH aplica modificaciones parciales.

    ⚠️ Ojo en los exámenes

    • Un error 4xx no siempre significa que el frontend tenga un bug; significa que el servidor no pudo o no quiso cumplir esa solicitud.
    • 500 no significa necesariamente que el servidor esté caído; indica que falló al procesar.
    • 304 es una respuesta de caché y no incluye una representación nueva en el body.
    • HTTPS es HTTP protegido por TLS, no un protocolo que cambie los métodos HTTP.
