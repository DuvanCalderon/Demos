La cocina y la fila de pedidos

En Capi Bolis, el cliente deja un pedido y recibe un número. La cocina procesa los pedidos pendientes cuando tiene capacidad. El backend puede hacer algo parecido: aceptar una tarea, colocarla en una cola y dejar que un worker la ejecute.

SIMULADOR 01 / CONTROL ROOM
Configura tu sistema
El reloj es virtual. Cada worker procesa una tarea a la vez. Primero ejecuta el efecto, luego espera ACK manual o automático al siguiente segundo. Puedes provocar una caída en esa ventana.




Cola limitada a 40 tareas en espera, incluyendo reintentos. Se rechazan nuevas publicaciones al llegar al límite. Las tareas en curso pueden regresar aunque se exceda ese límite: no se descartan silenciosamente. Los fallos de ejecución usan backoff exponencial; la caída de worker reentrega inmediatamente y no consume el presupuesto de fallos de ejecución.

Eventos del sistema
Una tarea entregada no está confirmada todavía. El efecto puede haberse ejecutado antes de que el broker reciba ACK. Si el mensaje se reentrega, el procesamiento puede duplicar el efecto: la idempotencia evita repetirlo en este modelo. En producción requiere persistencia, operaciones atómicas o mecanismos equivalentes.


SIMULADOR 02 / BACKLOG & THROUGHPUT
¿Cuántos workers necesitas?
Modelo por segundos: llegan N tareas, cada worker termina exactamente una tarea por segundo. Se atienden las pendientes primero. Se admite lo que cabe en una cola de espera de tamaño L, y se rechaza el excedente. No hay fallos ni reintentos en este escenario.
Una cola absorbe picos, pero si la llegada supera de forma sostenida la capacidad de servicio, crece la espera. Una cola finita obliga a aplicar control de entrada o rechazos. Escalar workers solo ayuda si otras dependencias soportan la carga.

SIMULADOR 03 / HTTP & BACKGROUND JOBS
¿El usuario debe esperar?
Compara una solicitud que genera un reporte directamente con una que crea una tarea de fondo. El modelo suma tiempos fijos: 100 ms para aceptar el trabajo; el worker comienza al terminar la espera en cola configurada. No modela sobrecarga adicional.
Cada POST reinicia este escenario. El código 202 significa aceptado, no completado; un endpoint de estado es una opción de diseño. El resultado puede fallar en sistemas reales.
